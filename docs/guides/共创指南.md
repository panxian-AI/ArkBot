# 共创指南

> 这份文档写给想改 ArkBot 的人：先讲清楚「哪一层负责什么」，再讲怎么加东西、怎么验证、怎么提交。
> 目标是让你在不读完全部源码的情况下，也能安全地做出第一个 PR。

---

## 1. 三层契约（先记这三句话）

```
┌────────────────────────────────────────────────┐
│ 插件层   plugins/*.py        「业务怎么说」      │  只依赖统一事件 + Bot 门面
├────────────────────────────────────────────────┤
│ 集成层   arkbot/integrations 「跟谁聊」          │  文本进、文本出
├────────────────────────────────────────────────┤
│ 核心层   arkbot/             「事件怎么流」      │  平台无关：事件/规则/消息链/调度
├────────────────────────────────────────────────┤
│ 适配层   arkbot/adapters/    「怎么连上 QQ」     │  换桥只改这里
├────────────────────────────────────────────────┤
│ 兼容层   arkbot/compat/      「别人怎么接进来」  │  对外扮演 OneBot 实现
└────────────────────────────────────────────────┘
```

1. **插件层不碰协议**：插件里不出现 `websocket`、`msg_id`、`group_openid` 这些词。
2. **核心层不认识平台**：核心只处理 `Event` / `MessageChain` / `Rule`。
3. **适配层只做翻译**：把某个平台的 JSON 翻成统一事件，把统一 API 调用翻回平台请求。

任何改动只要守住这三条，就不会把「换桥不换舟」的根基弄坏。

## 3. 环境与常用命令

```bash
pip install -e ".[dev]"      # 可编辑安装 + pytest
python -m arkbot             # 旧内核启动（读 bot.toml）
python -m arkbot2            # NG 内核启动
python -m arkbot2 --capabilities   # 看依赖候选清单
```

测试（全部离线，不需要 QQ）：

```bash
pytest tests/unit -q                  # 88 项单测：消息/规则/调度/持久化/聊天集成
python tests/e2e/e2e_test.py              # 单通道全链路
python tests/e2e/failover_test.py         # 双通道抗 ban 演练
python tests/e2e/arkbot2_compat_test.py   # 旧插件在新内核上零改动
python tests/e2e/persist_test.py          # 持久化冒烟
python tests/e2e/ai_chat_test.py          # AstrBot / DSH 聊天链路
```

提交前请至少跑 `pytest tests/unit` + 与你改动相关的那套 e2e。CI（`.github/workflows/ci.yml`）会在 Python 3.11 / 3.13 上跑全套。

## 4. 写一个插件（最常见）

```python
from arkbot import MessageSegment, Plugin, Rule

class Hello(Plugin):
    name = "hello"
    default_config = {"greet": "你好呀"}       # 可被 bot.toml 的 [plugins.hello] 覆盖

    async def onLoad(self):
        @self.on_command("hi", "打招呼")
        async def hi(event, state):
            await event.reply(f"{self.cfg['greet']}，{event.sender.nickname}")

        @self.on_keyword("在吗", block=False)
        async def here(event, state):
            await event.reply("在的", quote=False)

        @self.on_notice("group_increase")
        async def welcome(event):
            await self.bot.send_group_msg(
                event.group_id,
                MessageSegment.at(event.user_id) + MessageSegment.text(" 欢迎入群"),
            )

        @self.schedule_cron(minute="0", hour="8")
        async def morning():
            await self.bot.send_group_msg(123456, "早上好")
```

要点：

- 一个文件一个 `Plugin` 子类；文件名不要以 `_` 开头（会被跳过）。
- `on_command` 的 `state["args"]` 是命令后的原文；命令按**整词**匹配，`/echola` 不会命中 `/echo`。
- 回复默认带引用（`reply` 段）；群发不想引用就 `quote=False`。
- `self.cfg` 已经合并了 `default_config`，配置写在 `[plugins.<name>]`。
- 事件里 `event.to_me` 表示「这条消息是不是冲我来的」（@ 或私聊）。
- 插件里没有「平台」概念；想看底层信息用 `event.raw`，但不要依赖它的字段做业务判断。

⚠️ 不要在插件里做同步阻塞调用（`time.sleep`、`requests`）。要发 HTTP 用 `await asyncio.to_thread(...)`
或直接用 `arkbot.integrations.chat` 的 `post_json`。

## 5. 加一个平台适配器（抗 ban 的入口）

实现 `arkbot/adapters/base.py` 的三个核心：

```python
class MyAdapter(Adapter):
    name = "my-platform"

    async def connect(self) -> None:        # 建立连接、鉴权、断线重连
    async def call_api(self, action, params):  # 统一动作 → 平台请求
    async def send_reply(self, event, chain):  # 按来源回复（引用语义在这里落地）
```

然后在 `config.build_adapters()` 里加分支，`bot.toml` 写 `type = "my-platform"`。
事件侧只需构造 `Event.from_raw({...})` 后调用 `self._emit(event)`。

不需要继承基类也能用：`Bot` 只依赖 `name / is_connected / call_api / send_reply` 这几个属性（鸭子类型）。
NG 内核的 `Channel` 协议更宽松，测试里常用假对象直接注入。

先写一个假服务端（参考 `tests/fakes/fake_onebot.py`：`asyncio.start_server` + WebSocket），
再写 e2e 断言「发出的 API 调用参数正确」——这比连真号调试快得多。

## 6. 改兼容层（OneBot 服务端）

兼容层解决的**不是**「怎么连 QQ」，而是「已经写好的 OneBot 软件怎么继续用」。
`arkbot/compat/onebot11.py` 对外扮演一个 OneBot 11 实现，内部只依赖 `app.bot`，
所以两套内核（`arkbot` / `arkbot2`）共用同一份实现。

**加一个 API 动作**：优先什么都不做。默认分支会把未知动作透传给下游通道，
OneBot 实现原生支持就直接可用。只有「不依赖下游也能答」的动作才需要特判，
写在 `_dispatch()` 的本地分支里（例如 `get_login_info`）。

**改事件格式**：唯一入口 `to_onebot_event()`。三条硬要求：

- `message` 必须是数组（CQ 字符串在 `MessageChain.parse` 时已统一）；
- `self_id` 用当前登录号，不允许出现 0；
- 以 `_` 开头的内部字段必须过滤（如 `_official`）。

**加一种接入方式**（比如未来的 Satori / Milky）：在 `OneBot11Server.start()` 里
起一个后台任务，把收到的数据翻译成 `_dispatch()` 调用、把 `push_event()` 的
payload 翻译出去；网络层能复用 `WebSocketServer` 就不要引新依赖。

**改协议层要跑的测试**：`python tests/e2e/compat_test.py`（全链路，含真实 WS 客户端）
和 `pytest tests/unit/test_compat_onebot.py`（握手 / 鉴权 / 事件形状 / HTTP 语义）。
这两份测试是「别人写的软件能不能接上」的唯一证据，改动必须全绿。

一个常见坑：兼容层客户端和 ArkBot 插件会**同时**看到同一条事件，
两边都自动回复就是双份消息。写示例时要么只演示一边，要么在文档里写清取舍。

## 8. 规则与事件分发（改核心前必读）

- `Matcher = Rule + handler + priority + block`；按 `priority` 升序尝试，命中且 `block=True` 就停止传播。
- 规则可用 `&` 组合：`command("ban") & only_admin() & only_group()`。
- 消息事件在适配器侧就 `create_task` 分发（否则处理器里调 API 会与接收循环死锁——这是修过的真 bug）。
- NG 内核里 notice/request/meta 用 `asyncio.TaskGroup` 并发分发；中间件链在匹配之前执行。

改这里请务必跑 `tests/e2e/e2e_test.py` + `tests/e2e/arkbot2_compat_test.py`：它们覆盖了命令、关键词、通知、请求、定时、DI 与中间件。

## 9. 提交前检查清单

- [ ] `pytest tests/unit` 全绿
- [ ] 与改动相关的 e2e 全绿（改适配器跑 e2e；改兼容层跑 compat；改路由跑 failover；改插件系统跑 arkbot2_compat）
- [ ] 新增能力有测试（纯逻辑进 `tests/unit`，链路进 `tests/*.py`）
- [ ] 没有引入新运行时依赖（如确实需要，先在 `arkbot2/capabilities.py` 登记并做成软依赖）
- [ ] 文档同步：用户可见行为 → `README.md` 或 `docs/`；配置项 → `bot.toml.example`
- [ ] 不提交 `bot.toml`、`data/`、`*.egg-info/`、`debug.log`（`.gitignore` 已覆盖）
- [ ] commit message 说清「改了什么 + 为什么」，一个提交只做一件事

## 11. 风格约定

- Python 3.11+，`from __future__ import annotations`，类型标注尽量写全。
- 注释与文档用中文，变量/函数名用英文；注释解释「为什么」，不复述「做了什么」。
- 异步优先；需要阻塞调用一律 `asyncio.to_thread`。
- 日志用 `logging.getLogger("arkbot.<模块>")`，不要 `print`。
- 异常要么处理并记日志，要么往上抛；不要 `except Exception: pass`（线程边界除外，那里必须兜住）。
